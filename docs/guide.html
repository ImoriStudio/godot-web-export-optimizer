Web Export Optimizer

See what's in your Web build, right in the editor

This guide covers enabling the plugin, where its panel lives in the editor, how to read what it reports, and how to control what actually ships in a Web export.

1

Enabling the plugin

In Project → Project Settings → Plugins, find it in the list and switch it on. It stays active every time the project is opened.

4

Configuring your Web export

The report reflects whatever the active export preset is set to include. Three things worth checking on your own preset before relying on it.

Set a main scene

A Web build needs something to run when the page loads. Set one under:

Project → Project Settings → General → Run → Main Scene

Choose what ships

The Resources tab of the export preset controls the file list:

  • All resourcesdefaultEverything in the project, matching what this plugin's report assumes.
  • Selected scenesOnly the scenes you pick, and whatever they depend on.
  • Selected resourcesA hand-picked resource list and its dependencies.
  • All except checkedEverything, minus specific resources you uncheck.

Keep the optimizer out of your release

It's an editor tool — nothing in it runs at play time. Add this to the preset's exclude filter to leave it out of what ships:

addons/webexport_optimizer/*

5

The full loop

Six steps, always in this order — nothing runs on its own beyond the analysis itself.

  1. 1
    Turn the plugin on
    Project Settings → Plugins → toggle Web Export Optimizer. Once per project.
  2. 2
    Export for Web as usual
    Project → Export… with a Web preset — exactly as you would without the plugin installed.
  3. 3
    The panel refreshes itself
    As soon as the export finishes, the dock redraws with the new report — no button to press to see it the first time.
  4. 4
    Read the breakdown
    Category sizes, flagged textures, and orphaned assets — all sorted heaviest first.
  5. 5
    Apply a fix, if you want one
    Click Apply fix → a dialog spells out exactly what it will change → confirm. Nothing happens silently.
  6. 6
    Export again to check the result
    A second Web export refreshes the panel with the new total — the loop closes without leaving the editor.
About this guide: category names, file names and sizes shown here are examples, chosen to demonstrate how the report reads. The controls themselves (buttons, tree, confirmation dialog) are drawn to match what Godot actually renders.

Interface language: the panel follows Godot's own editor language (Editor Settings → Interface → Editor Language) — currently English and Italian are supported, with English as the fallback for anything else. The mockups above show Italian, since that's what this guide's screenshots were taken with; your own panel will match whatever language your editor is set to.

4

Configurare l'export Web

Il report riflette esattamente ciò che il preset di export attivo include. Tre cose da controllare sul proprio preset prima di fidarsi del risultato.

Imposta una scena principale

Una build Web ha bisogno di qualcosa da avviare al caricamento della pagina. Si imposta in:

Project → Project Settings → General → Run → Main Scene

Scegli cosa parte

La scheda Resources del preset di export controlla l'elenco file:

  • Tutte le risorsedefaultTutto il progetto — è ciò che il report di questo plugin assume.
  • Scene selezionateSolo le scene scelte e ciò da cui dipendono.
  • Risorse selezionateUn elenco di risorse scelte a mano e le loro dipendenze.
  • Tutto tranne le spuntateTutto il progetto, meno le risorse che deselezioni.

Tieni l'optimizer fuori dalla build finale

È uno strumento da editor — non serve a runtime. Aggiungi questo al filtro di esclusione del preset per lasciarlo fuori:

addons/webexport_optimizer/*

5

Il ciclo completo

Sei passaggi, sempre nello stesso ordine — nessuno automatico oltre l'analisi stessa.

  1. 1
    Attiva il plugin
    Project Settings → Plugins → interruttore su Web Export Optimizer. Una volta sola per progetto.
  2. 2
    Esporta per Web come sempre
    Project → Export… con un preset Web, esattamente come faresti senza il plugin installato.
  3. 3
    Il pannello si aggiorna da solo
    A export completato il dock si ridisegna in automatico — nessun bottone da premere per vedere i risultati la prima volta.
  4. 4
    Leggi il riepilogo
    Dimensioni per categoria, texture problematiche, asset orfani: tutto già ordinato dal più pesante.
  5. 5
    Applica una fix, se vuoi
    Click su Applica fix → una finestra spiega per intero cosa sta per cambiare → conferma. Mai un'azione silenziosa.
  6. 6
    Riesporta per verificare
    Un secondo export Web aggiorna il pannello con il nuovo totale: il ciclo si chiude senza uscire dall'editor.
Su questa guida: nomi di categorie, file e dimensioni mostrati qui sono di esempio, scelti per mostrare come si legge il report. I controlli (bottoni, albero, finestra di conferma) sono disegnati per corrispondere a ciò che Godot renderizza davvero.

Lingua dell'interfaccia: il pannello segue la lingua dell'editor Godot (Editor Settings → Interface → Editor Language) — al momento sono supportati inglese e italiano, con l'inglese come lingua di riserva per tutte le altre. Le immagini qui sopra mostrano l'italiano perché è la lingua con cui sono state fatte le catture; il tuo pannello mostrerà quella impostata nel tuo editor.
